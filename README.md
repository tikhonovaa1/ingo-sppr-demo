# СППР факторинга — бесплатная демонстрация для Render

Это **статический веб-сайт**, а не подключённая к Checko или банковской инфраструктуре система. Для публичной демонстрации он намеренно не содержит серверного API, секретов, базы данных и хранения заявок. Вводимые значения используются только в текущей вкладке браузера. Все финансовые показатели и индикативные лимиты — синтетические примеры; реальные ИНН не проверяются по внешним базам. Используйте тестовые данные, не вводите банковскую тайну.

## Публикация через GitHub + Render

1. Создайте учётную запись GitHub (https://github.com) и новый репозиторий `ingo-sppr-demo`, желательно **Private**. Не добавляйте реальные банковские данные или ключи.
2. Распакуйте ZIP. Загрузите **содержимое папки** (файлы `index.html`, `render.yaml`, `.gitignore`, `README.md`) в корень репозитория GitHub: Add file → Upload files → Commit changes.
3. Зарегистрируйтесь на https://dashboard.render.com и подключите GitHub, разрешив доступ только к нужному репозиторию.
4. Нажмите New → Static Site, выберите `ingo-sppr-demo`, ветку `main`. Build command: `echo ready`; Publish directory: `.` (точка). Выберите бесплатный вариант, если предложен. Нажмите Deploy Static Site.
5. Дождитесь статуса Live, откройте выданную Render ссылку `https://<имя>.onrender.com`. Конкретный адрес назначит Render.
6. Проверьте два тестовых ИНН, продукт, лимит, кнопку анализа, мобильный экран. Обновление страницы должно сбросить результат (никакого сохранения заявок).
7. После изменения файлов в GitHub Render может автоматически опубликовать новую версию (если Auto Deploy включён).

### Альтернативно: Blueprint

Можно использовать New → Blueprint и `render.yaml`, если выбранный интерфейс Render поддерживает static Blueprint. Ручное создание Static Site выше проще и не зависит от Blueprint.

## Безопасность и ограничения

- Нет запросов к Checko, ФНС или другим внешним сервисам.
- Нет сервера приложений, базы данных, cookie или localStorage приложения.
- Нет авторизации: **любой, кто знает публичный адрес, сможет открыть демонстрацию**. Приватность репозитория не делает сайт приватным.
- Render/GitHub могут иметь собственные технические журналы; не используйте реальные конфиденциальные значения.
- Для реального андеррайтинга понадобятся серверный backend, безопасная авторизация, защищённое хранение, контроль доступа, аудит, официальная методика и согласованная инфраструктура.
- Лимит и скоринг не являются рекомендацией банка и не могут использоваться для кредитного решения.

## Проверка локально

Откройте `index.html` в браузере. Для тестирования развертывания локальный Python и Docker не нужны.
