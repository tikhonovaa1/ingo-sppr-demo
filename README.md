# СППР — интеграция с Чекко

Сайт: https://tikhonovaa1.github.io/ingo-sppr-demo/
Сервер: https://ingo-checko-api.tikhonovaa38.workers.dev

## Работа
Введите код доступа СППР и ИНН сторон. Сведения запрашиваются автоматически после паузы ввода. Код и ключ API не сохраняются в исходниках сайта.

Автоматически заполняются наименование, регион, ОКВЭД, выручка, прибыль, капитал, обязательства, чистые активы при наличии строки 3600, отчётный год и источники. Последний завершённый отчётный год выбирается для каждой стороны отдельно. Финансы API в рублях переводятся в млн рублей. Пустое значение не подменяется нулём, капитал не подменяет чистые активы.

Арбитраж запрашивается с role=defendant и actual=true. В поле требований переносится ОбщСуммИск из ответа по этой выборке, статус определяется по ЗапВсего. Это не вывод о юридической обоснованности требований и не оценка существенности споров. Данные отражают актуальные дела в определении Чекко, а не только незавершённые дела.

Под финансовыми полями показаны ОГРН, КПП, дата регистрации, статус, адрес, сведения ФССП. Долг ФССП не подменяет обязательства бухгалтерского баланса. Если ответ ФССП состоит из нескольких страниц, отображаются показатели первой страницы с явной отметкой неполноты. Отсутствие сведений не считается отсутствием риска.

## Размещение
В GitHub Pages загружается содержимое site. Файл worker/index.js предназначен только для Cloudflare Worker; секреты CHECKO_API_KEY и SPPR_ACCESS_TOKEN задаются в Cloudflare. Существующее ограничение Origin сохранено. Неподдерживаемый Workers режим redirect:error заменён на manual, автоматическая передача ключа по перенаправлениям не выполняется.

## Проверка
Пройдены локальные проверки расчётов, нулевых и отрицательных значений, совпадения ИНН, ошибок, фильтра ответчика и сведений ФССП. В предыдущей версии реальный обмен четырьмя методами подтверждён для двух компаний. Новую полную подстановку необходимо подтвердить после публикации.

Система остаётся предварительной СППР. Критерии кредитной методологии не менялись. Условия тарифа, квоты API и полнота исходных сведений определяются Чекко.

## Методология приоритетности (обновление)
Реализованы пять ветвей первого и второго эшелонов из двух предоставленных пользователем фрагментов. Риск оценивается на дебитора, а при регрессе — дополнительно на клиента. Внутренние оценки ФП, платёжеспособности, финансовой независимости, устойчивости, кредитной истории и рейтингов вводит аналитик: числовых формул для этих оценок на фото нет.

Результат пересчитывается автоматически после завершения запросов и изменения формы. Это категориальное заключение, не числовой балл. 7/10 и подобные показатели означают только число заполненных финансовых полей. Порог обязательства/капитал >3 из прежней иллюстративной логики не используется в новой методологии.

Проверяются запрет предпоставочного факторинга, отсрочка ≤180 дней, опыт ≥6 месяцев, сопоставимый объём ±20% (с обязательным указанием периода и источника), импортный факторинг, отрасли и рыночные ограничения. Неприоритетность ведёт к индивидуальному рассмотрению, а не к запрету. Обеспечение и поручительство — положительные / желательные факторы.

Для лимита 50 млн рублей диапазон сопоставимого объёма — 40–60 млн рублей. Формулы одобряемого лимита и балльной шкалы в присланных фрагментах нет. Территориальные ограничения сохранены из исходного интерфейса и отдельно отмечены как отсутствующие на этих фото.

В корень GitHub Pages также обязательны methodology.js и methodology-ui.js. Внутренние оценки сбрасываются при повторной загрузке карточки, чтобы не переносить подтверждения между компаниями.
