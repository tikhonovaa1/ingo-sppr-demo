# СППР: автоматическая загрузка Чекко

Обновлённый интерфейс использует существующий сервер:
https://ingo-checko-api.tikhonovaa38.workers.dev

## Установка
1. Загрузите в корень существующего репозитория GitHub Pages все файлы из папки site: index.html, checko.js, ingo-logo.png и sppr-data-template.json. Замените прежние файлы. Новый файл checko.js обязателен.
2. Откройте https://tikhonovaa1.github.io/ingo-sppr-demo/ после завершения публикации и обновите страницу.
3. Введите код доступа СППР. Ключ Чекко в интерфейс не вводится. Код не сохраняется в браузере и в исходниках.
4. Введите ИНН клиента и дебитора. После паузы 0,8 секунды сведения запрашиваются автоматически. Кнопка позволяет повторить загрузку.
5. У каждой стороны отображается собственный результат загрузки. При смене ИНН прежние сведения и заключение сбрасываются.
6. Для финансов сначала подтвердите единицы ответа своего API по документации тарифа или контрольному ответу: рубли либо тысячи рублей. После выбора сведения загрузятся повторно. До подтверждения финансовые значения остаются пустыми.
7. Проверьте отчётные годы, регион, источники, укажите дату отчётности/источников и параметры сделки. Затем сформируйте заключение.

## Что перенесено автоматически
- Наименование, регион и код с названием основного ОКВЭД из распознанной карточки с совпадающим ИНН.
- Финансы из структуры data[год][код строки]: выручка 2110, чистая прибыль 2400, капитал 1300, чистые активы 3600 при наличии, обязательства как сумма 1400 и 1500. Поддерживаются числа и объекты с СумОтч. Данные переводятся в млн рублей только после подтверждения единиц пользователем. Берётся последний завершённый год из ответа; год отображается отдельно для каждой стороны. Капитал не подменяет чистые активы.
- Источник, время получения и год отчётности добавляются к заключению.

## Ограничения проверки
- Адрес существующего сервера проверен 31.10.2026: без авторизации возвращает HTTP 403 и разрешает Origin https://tikhonovaa1.github.io. Это подтверждает доступность сервера, но не доступ к Чекко и не правильность ключа.
- Проверены преобразования на искусственных ответах: нули, убытки, единицы, год, отсутствие данных и несовпадение ИНН. Реальные ответы вашего тарифа и работа в браузере после публикации пока не проверены.
- Документация https://checko.ru/integration/api/finances недоступна автоматическому просмотру (403). Структура финансов поддержана явно, без поиска чисел в произвольных вложениях. Её необходимо сопоставить с ответом вашего тарифа.
- Сервер должен возвращать прежний контракт: {results:{company:{ok:true,data:{...}},finances:{ok:true,data:{...}},"legal-cases":{ok:true,data:{...}},enforcements:{ok:true,data:{...}}},retrievedAt:"ISO-дата"}. Для ИП запрашивается entrepreneur; если существующий сервер не поддерживает этот метод, потребуется его обновление. Финансовая отчётность ИП не запрашивается.
- Арбитраж и ФССП запрашиваются, но суммы и отсутствие рисков автоматически не утверждаются: неизвестны фильтры роли и полнота страниц существующего сервера. Статус арбитража подтверждает аналитик. Ошибка метода не считается отсутствием риска.
- Автозагрузка делает до четырёх обращений к провайдеру на одну компанию через сервер. Повторная кнопка и изменение единиц создают новые запросы; учитывайте квоту API.
- Локальное открытие файла может блокироваться правилами доступа существующего сервера. Используйте настроенный адрес GitHub Pages.
- Пороги и текст кредитной методологии сохранены. Обновление не является валидацией методологии или банковским одобрением системы.

## Проверка после публикации
Введите код и тестовый ИНН, сверьте наименование и регион. Подтвердите единицы на известной отчётности и сравните значения и год. Замените ИНН: прежние показатели должны исчезнуть сразу. Проверьте неверный код, недоступный метод финансов и отдельную загрузку второй стороны. Не считайте подключение завершённым до этой проверки.
